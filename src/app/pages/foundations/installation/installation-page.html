• kui-field and kui-icon styles live in the kui.components layer, so both need kikita-ui.css like every other component. An unlayered application rule overrides them without raising specificity.
  • theme-default.css is part of @kikita-labs/ui/styles, so the default theme works from CSS alone. The generated theme sheet sits in the kui.tokens layer, declared before kui.base and kui.components, so a variable you write outside any layer wins regardless of source order.
  • provideKikitaUi() sets data-kui-density on <html> from seeds.density, on the server too, unless the page already set it.
  • Allow connect-src https://cdn.jsdelivr.net in a Content Security Policy, or serve the files yourself with createKuiLucideResolver and provideKuiIcons, and opt out of the default set with provideKikitaUi({{ '{' }} icons: false {{ '}' }}).
  • A name that is not a Lucide kebab-case name resolves to nothing without a request, and structural icons never use the network.
  • The migration renames only identifiers (rename-symbols-v2) and skips strings, comments and templates. Names used through a dynamic import are not seen, so search for the old suffixes with git grep.
  • If you render on the server, check that a cache in front of it sends Vary: Accept-Language.
