• A signal only needs to be readable; the toast never writes to it, so a computed works.
  • Turning the signal true freezes the time left and false resumes it. A toast opened with a true signal starts the full duration the first time the signal becomes false.
  • ref.update({{ '{' }} persistent {{ '}' }}) or ref.update({{ '{' }} duration {{ '}' }}) restarts the full duration. An update that omits persistent keeps the current binding; one that sets it replaces the previous value or signal and detaches the old signal.
  • An explicit persistent value, even false, wins over duration: Infinity; a non-finite or missing duration then uses the default duration.
  • Updates after the toast starts closing are ignored. Closing the toast or destroying the region detaches every signal subscription and timer and completes closed$ and action$.
  • The toast region has aria-live="polite", so new toasts are announced without interrupting current speech.
  • Toasts do not capture keyboard focus on appear, unlike Dialog. Keep critical, blocking confirmations in a Dialog instead of a toast.
  • Hovering a toast pauses its auto-dismiss timer; leaving resumes it with the remaining time. This gives pointer users time to read before it disappears, but there is no keyboard-equivalent pause gesture documented yet — treat persistent as the safer choice for messages a keyboard-only user must be able to act on.
  • Set persistent for errors or messages requiring a response instead of relying on the default 5 second auto-dismiss.
  • A persistent toast can still be dismissed by its close button, by KuiToastRef.close(), or by the owning service's dismiss() and dismissAll() methods.
  • prefers-reduced-motion replaces slide animations with an opacity-only fade.
  • The region is named by the toast.region message (Notifications). While toasts are visible it is a manual popover in the browser top layer, alongside Dialog, Drawer and Menu.
  • On narrow screens the card stretches to the viewport width and aligns to the bottom edge.
  • On the server, KuiToast.open() returns a no-op ref and performs no DOM access, so calling it during SSR is safe.
  • provideKuiToastOptions and KUI_TOAST_OPTIONS are replaced by defaults.toast through provideKikitaUi({{ '{' }} defaults {{ '}' }}) or provideKuiDefaults; position and maxVisible follow runtime changes of the default.
  • The service class is KuiToast (was KuiToastService); kuiToast() still returns it.
  • The notification region name comes from the toast.region message, and the close glyph from defaults.toast.closeIcon or defaults.icons.close.
  • While toasts are visible the region is shown in the top layer, so it stays above open Dialogs and Drawers.
  • Close button, message and title colours have tokens, and the close radius and accent width have geometry tokens.
