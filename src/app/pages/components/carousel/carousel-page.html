ariaLabel defaults to the carousel.label message (Slides) and should name the content. It must not contain the word carousel: the region's aria-roledescription="carousel" already announces it. The height comes from the slide content, so set a block-size on the carousel root with ordinary CSS if you need a fixed one.

The track's aria-live is off while autoplay is advancing and polite whenever it is paused, so manual navigation is still announced.

  • Touch swipe and trackpad scroll always work through the native overflow-x: auto; a debounced scroll listener snaps index to the nearest slide once scrolling settles.
  • showArrows="false" with showDots="false" (swipe only) is reachable but not self-sufficient under WCAG 2.5.7 (Dragging Movements).
  • The outer element is role="region" with aria-roledescription="carousel" and the ariaLabel; each slide is role="group" with aria-roledescription="slide" and an N of total name.
  • The dot picker is a tablist of tabs with aria-selected, aria-controls pointing at the slide id and a roving tabindex; arrow keys, Home and End move focus and selection.
  • The region also responds to ArrowLeft, ArrowRight, Home and End to change slide, independent of dot focus.
  • While draggable is true the scrollable track is a keyboard tab stop (tabindex="0") with a visible focus ring; with draggable="false" it is not.
  • Prev, Next, Play and Pause are kuiIconButtons with a required aria-label. At the range boundary (without loop) Prev or Next gets the native disabled attribute and leaves the tab order.
  • Play/Pause order and pausing on hover and focus follow the W3C APG auto-rotating carousel. autoplay with arrows, dots and dragging all disabled leaves no way to pause by hand, which conflicts with WCAG 2.2.2; use it only for purely decorative rotation.
  • There is no per-breakpoint itemsPerView; it is a plain number.
  • The carousel has no size prop: it always sizes to its container, and the controls inherit their size from the kit's size and density context.
  • A formal assistive-technology review with a real screen reader has not been run, and a narrow mobile viewport was not verified by the library review.
